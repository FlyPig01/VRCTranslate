## 2. 文案正文（可直接落进 XAML 的字符串）

## 4. 取舍说明

| 决定 | 原因 |
| --- | --- |
| 用表格而不是三行推荐 | 用户要求的：让用户自己按「快 / 准 / 便宜」判断，推荐只做兜底 |
| 延迟只写翻译服务本身 | 用户要求的：VAD 600 ms、本地识别 ~200 ms 不是选服务的原因，且以后会改（换模型/调参数都会变）。表里只放**这次调用**的耗时 |
| 写实测中位而不是区间 | 表格里放区间（如 88~3047 ms）会占三行且看不懂；P90 与最大值的明细留在实验报告 |
| 免费额度与价格写进表 | 用户选服务时会看这个；都标了「以官网为准」 |
| 大模型的「改写中文」写进表 | 这是选机翻还是选大模型的真实依据；不写等于让用户踩坑 |
| 「价格」列用「约」 | 两家大模型按 tokens 计费，字符与 token 不是 1:1，只能给量级 |

## 6. 待你决定的两点

1. **表格放 5 行还是 3 行？** 5 行信息全但占地方（本卡片会变长）；3 行（去掉阿里通用版、小米）最清爽，但用户看不到「阿里有两个版本」和「小米更便宜」。**我建议 5 行**，理由是这个页面是「配置一次就不再来看」的页面。
2. **腾讯的价格要不要写？** 官方页面只给了预付费资源包（≈55 元/百万字符），后付费单价需要再核。可以先写「约 55~58 元/百万字符」，或干脆留「以官网为准」。
