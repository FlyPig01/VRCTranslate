# 翻译服务配置简化方案

> **状态：待审核（未改代码）**
> **本版修订（2026-09-16）**：按代码核对结果修订 9 处，主要变化——
> ① **服务商由 3 家更正为 4 家**（小米 MiMo 已接入，见提交 `fb8ed2f`）；
> ② 免费额度数字经用户确认有效，但**仅作对话框提示，并注明"以官网为准"**；
> ③ 「保存即验证」**不再作为保存门槛**，改为独立的「测试连接」按钮；
> ④ 补充「阿里云会丢弃错误码、精确提示需要改一行 Provider」这一实施障碍；
> ⑤ 明确标出本方案与**此前"档1 排除"决定**的关系（见第七节）；
> ⑥ **密钥获取引导改放「指南」页**（用户决定），档案对话框里只留一句指向它。
>
> 背景：腾讯云 / 阿里云机器翻译有存在价值（免费额度大、延迟低、质量稳定），但当前配置表单太繁琐。本文给出三部分结论：配置如何简化、是否自营翻译服务、能否用网页版免费服务。

## 一、现状问题：配置太麻烦的根因

当前"新增翻译服务档案"对话框（`TranslationPage.xaml.cs` 的 `ShowProfileDialogAsync`）一次展示 **7 个平级字段**，
覆盖 **4 家**服务商（小米 MiMo 已接入）：

| 字段 | 腾讯云 | 阿里云 | DeepSeek | 小米 MiMo | 处理 |
| --- | --- | --- | --- | --- | --- |
| 档案名称 | 保留（多档案场景需要自定义名） | 保留 | 保留 | 保留 | 保留，预填建议名（防重名） |
| 服务类型 | 必填 | 必填 | 必填 | 必填 | 保留 |
| 模型或接口版本 | 无真实选项（仅 `TextTranslate`） | **有真实选项**：通用版 / 专业版 | 自由文本（`deepseek-flash` 默认） | 自由文本（`mimo-v2.5` 默认） | 按服务商变形（见下） |
| 接口地址 | 已默认 | 已默认 | 已默认 | 已默认 | **收进高级折叠** |
| API 密钥 | 必填（SecretId） | 必填（AccessKey ID） | 必填（API Key） | 必填（`sk-` 单密钥） | 保留 |
| Secret/SecretKey | 必填 | 必填 | — | — | 保留 |
| 区域（可选） | 默认 ap-beijing | 默认 cn-hangzhou | — | — | **收进高级折叠** |

**根因不是"字段多"，而是把无需用户决策的接口地址 / 区域当成平级字段展示**，
且模型字段对所有服务商都是自由文本（阿里云的"通用 / 专业"被表达成一个莫名其妙的 general/professional 输入框）。

**阿里云版本说明（已按代码核对）**：机器翻译分**通用版**与**专业版**（以及专业版-垂直领域），
**两者都有每月 100 万字符免费额度**（用户已确认；主账号，子账号共享），超量后通用版 50 元 / 百万字符、专业版 60 元 / 百万字符。

代码现状（`TencentAliyunTranslationProviders.cs`）：

```csharp
["Scene"] = Option(options, "scene")
    ?? (request.Model.Equals("professional", StringComparison.OrdinalIgnoreCase) ? "professional" : "general")
```

即 **`Options["scene"]` 优先，`Model` 只是兜底**。所以下拉框应当写 `Options["scene"]`，
不要把"通用/专业"继续塞进 `Model`——`Model` 在腾讯那边是 Action、在 DeepSeek/小米那边是模型名，语义已经很杂。

**两个必须提前知道的技术障碍**（原方案未提）：

1. **阿里云 Provider 目前会把错误码丢掉**：抛出时只取 `Message`（同文件第 151-152 行），
   而腾讯那边错误码是带在异常消息里的。要做"精确的中文提示"，**必须改这一行 Provider**——
   所以"零改动 Provider"这个前提不成立。
2. **腾讯 / 阿里的密钥前缀不是强制的**：`AKID` / `LTAI` 只是控制台生成时的命名约定，用户可自定义。
   粘贴识别只能把它当**提示**，不能当唯一判据（见 2.1）。

## 二、简化方案（保留服务商，只改配置体验）

### 2.1 表单分层与字段变形

**常规区（默认可见）**——档案名称、服务类型、按服务商变形的"模型/版本"、密钥 1~2 个：

| 服务商 | 常规区字段 |
| --- | --- |
| **腾讯云** | 密钥 ×2（SecretId / SecretKey）。**模型字段隐藏**（只有 `TextTranslate` 一个 Action，没有可选项） |
| **阿里云** | 版本**下拉框**：`通用版（默认）` / `专业版`，两项都标注"每月 100 万字符免费"，**写入 `Options["scene"]`**（不是 Model）；密钥 ×2 |
| **DeepSeek** | 模型**自由文本**，预填 `deepseek-flash`；密钥 ×1 |
| **小米 MiMo** | 模型**自由文本**，预填 `mimo-v2.5`（`mimo-v2.5-pro` 实测单句 1.7~2.3 s，模型卡片可提示"pro 不推荐"）；密钥 ×1（`sk-` 单密钥） |

> **模型字段刻意不统一**：只有阿里云的"通用/专业"是真正二选一的语义，才做下拉；
> DeepSeek / 小米保持自由文本——官方模型线更新快，写死下拉会过期（这一条与审查意见一致）。

**档案名称**：保留输入框 + 按服务商预填建议名（"腾讯云翻译" / "阿里云机器翻译" / "DeepSeek" / "小米 MiMo"），
**重名自动加序号**（"小米 MiMo 2"），空名仍兜底成"新的翻译服务"（现有行为）。

**高级设置（Expander，默认折叠）**——接口地址（预填默认值）、区域（腾讯 / 阿里显示），
标注"已预填，通常无需修改"。**折叠而非删除**，保留自定义网关 / 私有化部署的逃生口。

**密钥粘贴识别**（容错优先）：

- 支持多种形态一次粘贴自动拆分：**两行**、**Tab/空格分隔**、`SecretId=xxx&SecretKey=yyy` 这类键值对；
- `AKID` / `LTAI` 前缀只作为**排序提示**，**不作为判据**（用户可以在控制台改成自定义名）；
- 拆不出来时**不报错**，保留原文并提示"请分别粘贴两个密钥"。

### 2.3 测试连接（原"保存即验证"）

**改为独立的「测试连接」按钮，不再把验证当作保存的门槛**（原方案的"保存即验证"会被欠费 / 限流 / 临时断网卡住，
用户连"先存着待会儿改"都做不到）：

- 按钮旁边一句话说明：**"会向该服务发一句测试文本（会计入你的用量）"**——这是外发请求，必须让用户知情；
- 成功 → "✓ 连接正常，翻译服务可用"；
- 失败 → 映射成中文提示并**保留表单**，用户可以直接改；
- **保存永远允许**，哪怕从未点过测试。

**失败提示需要一张错误码映射表**（不写全，这个功能就只是句空话）：

| 服务 | 原始错误 | 提示 |
| --- | --- | --- |
| 腾讯云 | `AuthFailure.SignatureFailure` | SecretId 与 SecretKey 不匹配，请重新复制（注意不要带空格） |
| 腾讯云 | `AuthFailure.SecretIdNotFound` | SecretId 不存在或已删除，请到访问管理重新生成 |
| 腾讯云 | `FailedOperation.NoFreeAmount` / `LimitExceeded` | 免费额度已用完或触发限流，请稍后重试或充值 |
| 腾讯云 | `FailedOperation.UserNotRegistered` | 该账号还没开通"机器翻译 TMT"服务 |
| 阿里云 | `InvalidAccessKeyId.NotFound` | AccessKey ID 不存在 |
| 阿里云 | `SignatureDoesNotMatch` | AccessKey Secret 不匹配 |
| 阿里云 | `Throttling` / `Throttling.User` | 触发限流，稍后重试 |
| 阿里云 | `Forbidden` / `InvalidAction` | 子账号未授权"机器翻译"或版本不支持 |
| DeepSeek / 小米 | HTTP **401** | API Key 无效或已被撤销 |
| DeepSeek / 小米 | HTTP **402 / 余额不足** | 账户余额不足，请充值 |
| DeepSeek / 小米 | HTTP **429** | 触发限流，稍后重试 |
| 全部 | 超时 / 网络异常 | 网络不通或服务不可达（不影响保存） |

> ⚠️ **实施障碍（原方案未提）**：**阿里云 Provider 现在把错误码丢掉了**——抛出时只取 `Message`
> （`TencentAliyunTranslationProviders.cs` 第 151-152 行），而腾讯那边错误码在异常消息里。
> 要做到上表这种精确提示，**必须改这一行 Provider**（把 `Code` 一起带进异常消息），
> 所以"Provider 零改动"不成立。DeepSeek / 小米侧已经带 HTTP 状态码，可直接用。

### 2.4 实施成本与验收

**分两步走，不要一次做完**：

| 步骤 | 内容 | 工作量 | 风险 |
| --- | --- | --- | --- |
| **A0（先做）** | **指南页新增「翻译服务配置」卡片**：四家控制台直达链接 + 开通要点 + 额度（标注以官网为准） | 约 **半天**（1 张卡片 + 1 个打开链接的方法 + 脚本断言） | 低：只加一张卡片，不动任何现有逻辑 |
| **A（接着做）** | 「测试连接」按钮 + 错误码映射（四家）+ 对话框里那句"见指南页" | 约 **1 天**（含 1 行 Provider 改动、新单测、脚本断言） | 低：不改布局、不动数据模型 |
| **B（后做）** | 表单分层（接口地址 / 区域收进高级折叠）、阿里云版本下拉、腾讯隐藏模型、粘贴识别、预填名防重名 | 约 **1 天**（纯 UI 层，重构 `ShowProfileDialogAsync`） | 中：会动到现有对话框布局与"按服务商变形"逻辑 |

**验收标准（A0）**：指南页出现「翻译服务配置」卡片；四家的"打开控制台"链接都能拉起浏览器到正确页面；
额度数字旁有"以官网为准"；已有断言「指南页不得出现硬编码的出厂快捷键默认值」继续为非空 → **不新增硬编码默认值**。

**验收标准（A）**：填错 SecretKey → 点测试连接 → 出现"SecretId 与 SecretKey 不匹配"中文提示且表单保留；
填对 → "✓ 连接正常"；**不点测试也能保存**。

**验收标准（B）**：新增腾讯档案 = 起名 → 选类型 → 粘贴两段密钥 → 直接保存；
阿里云版本是下拉选择；接口地址与区域默认不可见；DeepSeek / 小米模型仍是自由文本。

## 三、自营翻译服务（我架后端、用户向我付费）的成本评估

**结论：不建议现阶段做。技术上一行中转代码的事，合规和运营是大头。**

面向公众收费提供服务，需要面对（按顺序）：

1. **ICP 备案**：国内服务器 + 域名必须办（个人可办，数周）
2. **增值电信业务经营许可证（ICP 许可证）**：经营性互联网信息服务严格来说需要，且要求**企业主体**（注册资金、人员等），个人开发者难以办理
3. **收款渠道**：微信/支付宝商户号需要营业执照（个体工商户注册门槛低但也是主体）；个人收款码收"服务费"属灰色
4. **发票与税务申报**
5. **内容合规**：面向境内公众提供生成式 AI 服务受《生成式人工智能服务管理暂行办法》约束；借 DeepSeek 这类已完成备案的模型 API 构建应用通常由模型方覆盖，但自营收费渠道建议先做法律咨询
6. **上游条款**：DeepSeek 开放平台协议授予的是"可撤销、不可转让、非独占"许可，对转售/转租有限制——"集成到应用里服务最终用户"通常允许，**裸转卖 API 访问被禁止**；自营中转站在这条边界上
7. **持续运营**：计费、限额、防刷、客服、共享 Key 被盗刷的风险

**轻量替代（推荐）**：

- 维持 **BYOK**（用户自己的 Key）模式 = 零合规负担
- 把免费额度引导做好（第二节，**已决定放在「指南」页**）：腾讯每月 500 万字符对个人语音字幕完全够用，**等于免费用**
- 想支持项目 → 捐赠/赞助模式（爱发电、GitHub Sponsors），不与功能绑定
- 远期可内置 LibreTranslate / 本地 LLM 作为完全免费合规的离线兜底

## 四、用网页版免费服务是否违规

| 路径 | 结论 |
| --- | --- |
| 用户自己用浏览器翻译网页 | 正常使用，无违规；但与软件无关（浏览器内部功能没有公开 API，软件无法合法调用，hook 浏览器属逆向） |
| 程序化调用网页版 DeepSeek（chat.deepseek.com，含各类逆向/免费桥接项目） | **违反服务条款（不是"违法"）**。用户协议授予的是可撤销许可，程序化访问未获授权（官方指定的程序化通道是付费 API）；后果：**封号、接口随时失效、承担违约责任**。**不做** |
| 各家免费 API 额度 | **合法免费**：腾讯 TMT 500 万字符/月、阿里云 100 万字符/月、DeepSeek 与小米充值使用（实测约 0.00004~0.00007 元/句） |
| 自建开源翻译（LibreTranslate/Argos、本地 LLM） | 合规免费，质量低于商业服务，可作远期离线选项 |

## 五、决策建议

1. **保留腾讯 / 阿里 / DeepSeek / 小米四家**，并按第二节分三步（A0 指南页 → A 测试连接 → B 表单分层）简化配置体验——
   但**"唯一合法免费来源"这个说法要更正**：腾讯 500 万字符/月、阿里 100 万字符/月确实是大额度免费，
   DeepSeek 与小米按实测约 0.00004~0.00007 元/句（每月一万句 ≈ 0.4~1.4 元），**同样属于"实际上免费用"**；
2. **不自营收费翻译服务**——合规成本与个人项目体量不匹配；
3. **不接网页版逆向接口**——不可靠且违约；
4. 远期可选：内置本地开源翻译作离线兜底。

## 六、本方案实施前必须明确的遗留点

1. **阿里云下拉写 `Options["scene"]`**，不要写 `Model`（现有代码 `Options` 优先，Model 只是兜底）；
2. **腾讯的 `Action` 仍取 `Model`**（现有代码：`action = Options["action"] ?? Model ?? "TextTranslate"`）——
   隐藏模型字段时必须保证 `Model` 保存成 `TextTranslate`，否则腾讯会拿到空 Action；
3. **错误码映射必须先改阿里云 Provider 那一行**（带出 `Code`），否则上表有一半提示实现不了；
4. **模型字段只有阿里云做下拉**，DeepSeek / 小米保持自由文本；
5. **粘贴识别以前缀为提示、不以它为判据**；
6. **额度数字进 UI 时必须带"以官网为准"**（数字已验证，但云厂商会调整）；
7. 已有一个入口可以顺手复用：**点击"未配置的预设档案"会直接打开编辑对话框**（提交 `cc80c47` 加的守卫），
   它正好是"引导用户去填密钥"的天然入口，不必再新造一个；
8. **指南页要加断言**（防回归）：卡片存在、四个控制台链接的 `AutomationId` 都在、且页面上不得出现密钥/示例密钥；
   同时**不要碰**既有的"指南页不得硬编码快捷键默认值"断言；
9. **点击链接的实现**：WinUI 3 的 `HyperlinkButton` 没有 `NavigateUri`，必须代码里 `Process.Start(UseShellExecute: true)`；
   四个链接共用一个处理器（`Tag` 传 URL），失败时给个 InfoBar 提示而不是静默。

## 七、与既有决定的关系（必须确认）
