# 免责与边界声明（叠甲）

> 状态：**待用户确认**。确认后落地到软件（指南页一张「使用声明」卡片）与仓库（`DISCLAIMER.md`）。
>
> 目的有两个，分开写，别混在一起：

## 一、软件自身的免责（防投诉、防索赔）

> - **不修改游戏**：本软件不读写 VRChat 进程内存、不注入、不修改游戏文件；音频通过 Windows 系统回环采集，字幕通过 VRChat 官方支持的 OSC Chatbox 发送。

### 这一段为什么这么写

| 条款 | 防的是什么 |
| --- | --- |
| 非官方 | 有人以为这是 VRChat 官方工具，出问题去找官方，或反过来官方认为你冒用名义 |
| 不修改游戏 | VRChat 对「第三方修改客户端」的容忍度极低，必须明确划清——我们只用系统回环 + 官方 OSC |
| 可能出错 | 翻译错了导致社交事故、交易纠纷，作者不背 |
| 费用自理 | 有人密钥没管好被人刷爆账单，回头找作者 |
| 无担保 | MIT 原文已有，这里用中文再写一遍，让不看英文的人也能看到 |
| 不外发数据 | 隐私是社区敏感点，写清楚能省掉一轮质疑 |

## 二、「作者的小店」的边界（防被骂）

建议放在小店卡片上的原文：

> 小店里卖的是**作者自己的** VRChat 模型、工程文件与素材，与这个翻译工具无关；
> **不买也能用全部功能**，软件没有隐藏付费项、不会因为你没买而限制任何功能。交易与售后由作者在小店内直接处理。

### 为什么必须写这两句

- 「**不买也能用全部功能**」——社区最反感的模式是「开源外壳 + 关键功能收费」。写明这句，别人就骂不进来；
- 「**与这个翻译工具无关**」——防止有人以为买软件送模型、或买模型才能用软件；
- 「**交易与售后在小店内处理**」——把纠纷留在交易平台内，不要引到软件仓库的 issue 区。

## 三、作者该自己把握的（我只能给建议，不能替你保证）

这一节我不写进软件文案，因为**这是你店铺的事，不是软件的事**。但你要卖模型/工程/素材，下面几条决定了会不会被骂：

| 风险点 | 建议 |
| --- | --- |
| 素材来源 | 只卖你有权出售的（自制、买断、授权允许转售）。**别卖来路不明的资源**——那是唯一会真正招黑的地方 |
| 是否二创别人的模型 | 商品页写清「基于 xxx 改模，原作者 xxx」，别让人误会是原创 |
| AI 生成内容 | 如果模型/贴图是 AI 生成的，商品页标注。VRChat 圈对 AI 素材的容忍度正在收紧 |
| 工程文件 | 如果工程里含付费插件或他人资产，说明依赖关系，不要让买家以为能直接转售 |
| 被投诉时 | 下架 + 说明，比争论便宜得多 |

**一句实话**：软件这边我能用文案把边界划清楚；店铺那边会不会被骂，取决于卖的东西干不干净，这个我替不了你。

## 五、不写进软件的（避免自找麻烦）

| 不写 | 原因 |
| --- | --- |
| 「保证不会被封号」 | 无法保证；写了反而成为把柄 |
| 任何法律条款的自我解释（例如「本声明具有法律效力」） | 外行写法律条款只会更糟；MIT 许可证本身已经覆盖授权与担保 |
| 退款/售后承诺 | 那是店铺的事，写进软件等于把店铺责任绑到项目上 |
| 对 VRChat 服务条款的解读 | 让用户自己看官方条款，别替官方解释 |
