# 兼容性要求（分发前提）

软件要分发给他人使用，兼容性是**硬约束**：新功能只能锦上添花，不能让老系统上原本可用的能力失效、报错或崩溃。
本文件是所有后续改动的验收前提；与具体方案冲突时，以本文件为准。

## 支持范围

| 项 | 决定 | 现状 |
| --- | --- | --- |
| 最低系统 | Windows 10 2004（Build 19041），与 `TargetPlatformMinVersion` 一致 | ✅ 与项目设置一致 |
| 架构 | win-x64（ARM64 Windows 走 x64 模拟，未做原生支持） | ✅ 明确范围 |
| 运行库 | 自包含 .NET 10 + 自包含 Windows App SDK，**用户不需要安装任何运行时** | ✅ 已自包含 |
| 数据位置 | 便携：程序目录 `data\`；程序目录不可写时回退 `%LOCALAPPDATA%` 并在设置页写明 | ✅ 已实现 |
| 部署形态 | 解压即用（zip / 安装器），不写注册表、不要求管理员权限 | ✅ 便携式 |

| --- | --- | --- | --- |

## 硬性禁止（分发红线）

1. **调用前必须检测**：任何新 API 在使用前做能力/版本检测；检测失败不得抛出到用户可见路径。
2. **失败必须保留原有能力**：进程回环失败 → 系统回环继续工作；GPU 失败 → CPU 继续工作。
3. **不得抬高门槛**：新功能不得提高最低系统版本、不得要求用户安装运行库、不得要求管理员权限。
4. **不得静默降级**：用户以为"只抓 VRChat"而实际抓的是系统混音，必须在界面可见（Phase 4 的来源徽标）。
5. **可选组件缺失一律走"功能关闭"**，不得表现为"启动失败"：模型、驱动、设备、系统版本都属此类。

## 验证方式

- **自动**：能力检测与降级路径必须有单测固定。换人切分需覆盖“标签关闭仍切分、标签开启再附加身份、模型缺失/失败退回整段、自身语音不切分”。注意本机为 Windows 11 Build 26200，`< 20348` 分支**在本机无法真机覆盖**，属结构性测试盲区，只能靠单测 + 代码审查。
- **自动（Phase 3 新增）**：进程回环的能力门控用注入的 Build 单测固定，`< 20348` 只验证"不尝试、不激活"；官方进程回环本身由受控双进程测试音集成测试真跑（Build ≥ 20348 且存在活动播放端点时才运行，否则明确 Skip，不假通过）。
- **真机（本机可覆盖）**：≥20348 全路径、无默认输出设备、设备运行中拔出、模型缺失、程序目录只读（回退 `%LOCALAPPDATA%`）。
- **分发前冒烟**：在干净机器上（无 .NET、无 Windows App SDK、无模型缓存）解压即用，确认不弹运行时缺失、不要求联网。
