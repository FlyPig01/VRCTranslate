## 1. 为什么需要这段文案

实验结论里有三条直接影响选型，但用户在「新增档案」时看不到：

| 事实 | 数据 | 对用户的影响 |
| --- | --- | --- |
| 机翻比大模型快一倍以上 | 阿里专业 195 ms vs DeepSeek 495 ms vs 小米 696 ms（p<0.0001） | 默认选机翻，字幕更跟得上说话 |
| 机翻对游戏专有名词和粤语有系统性盲区 | 日语「ワールド」→ 腾讯译成「周游世界」；韩语「렉(lag)」→ 腾讯译成**人名「雷克」**；粤语机翻**全部原样退回** | 讲粤语或在意日语时得加大模型 |
| 机翻把中文原样退回，大模型会轻微改写 | 中文条目 chrF2：机翻 100.0，DeepSeek 93.7、小米 64.6 | 在意「字幕和对方原话一模一样」的人选机翻 |

## 3. 文案正文（可直接落进 XAML 的字符串）

### 3.2 三行推荐（每行 = 编号 + 服务名 + 场景标签 + 右侧延迟徽标）

### 3.3 每行下面的说明（次要文字色，自动换行）

```
① 比大模型快一倍多，游戏专有名词译得最准；讲粤语的人请选 ③。
② 每月免费额度最大；个别口语词会直译（如「服务器正在苦苦挣扎」）。
③ 粤语能翻译、日语最准；中文会被轻微改写（例如「开饭时间」→「用餐时间」），意思不变。
```

### 3.4 收尾一句（次要文字色）

```
不确定就用 ①；听过粤语或日语译得别扭，再切 ③ 试试。
```

## 4. 三条文案的取舍说明（为什么这么写）

| 决定 | 原因 |
| --- | --- |
| 用「约 X 秒」，不写 195 ms | 用户感知的是「说完一句到字幕出现」，那个数含 VAD 600 ms 与识别 165 ms：机翻 ≈ 0.96 s、DeepSeek ≈ 1.26 s。写毫秒会让人以为是纯翻译耗时 |
| 只推荐 3 家，不列 5 家 | 小米质量不差但最慢（696 ms，P90 1488 ms）；阿里通用版被专业版全面压制（质量与延迟都输）。列 5 家只会让人选不出来 |
| 用「游戏专有名词」而不是「术语」 | 实测翻车的就是 ワールド / avatar / 렉 这类游戏词，说清楚才对得上用户遇到的现象 |
| 明说 DeepSeek 会改写中文 | 这是实测事实（chrF2 93.7），不写等于隐瞒；写了用户可以自己判断能否接受 |
| 不写价格对比 | 各家价格会变，引导页已有「以官网为准」的说明；价格不是选型决定因素（实验报告 §7.1） |
| 明说大模型会改写中文，但不说「这是 bug」 | 用户已决定**不做汉字跳过**（D15：延迟与语种无关，且影响以后多语种扩展）。所以「改写」是当前设计的**可接受代价**，文案只需让在意逐字一致的人能据此选机翻档 |

## 6. 备选方案（如果你觉得三行太多）

**极简版**：只留一行。

```
不确定选哪家？先用「阿里云 专业版」——机翻里最快最准；讲粤语或在意日语时再换成「DeepSeek」。
```

优点：界面最干净，改动最小。缺点：没有延迟数字，用户不知道差多少。

**我建议用完整版（§3）**，理由是这个页面本来就是「配置一次、以后不再来」的页面，多三行不会造成负担，但能省掉用户来回试错的时间。
