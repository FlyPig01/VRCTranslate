# 待办缺陷与改进记录

用户确认后才执行。每条记录现象、影响、方向与状态；标注「待排期」的条目**不实现**。

## D1 · 他人语音长对话消息堆叠，无法查阅

- **状态：已实施**（消息条滚动列表：每条一句、可上下回看、新消息自动滚到底；不持久化、无清空入口；暂停保持现状）
- **现象**：语速很快的长对话里，字幕把连续多句一次性堆在一起输出，成了一整块文字，无法逐条查阅。
- **期望**：改成消息条滚动列表（类似 QQ / 微信）——每条一句、可上下滚动回看历史、新消息自动滚到底。
- **影响面**：只涉及字幕的呈现与消息模型（`SubtitleOverlayWindow` / `OverlayWindowHost` / `SubtitleSpeechSession` 的输出路径），**不涉及识别与翻译链路**。

### 已确认的产品决定

| 问题 | 决定 |
| --- | --- |
| 是否持久化历史 | **不持久化**：消息只存在于当前运行期间，不写磁盘 |
| 是否提供「清空」 | **不提供**清空按钮 |
| 暂停时的行为 | **保持现状**：暂停即停止追加，不清空、不改变已有消息 |
| 与现有「原文 + 译文」结构 | **合并为同一条消息**，不新增一层结构 |
| 呈现内容 | **可选**：仅译文 / 译文 + 原文 |
| 说话人标签 | 开启说话人区分时随消息呈现（沿用现有标签） |

### 实施决定（原「待定」项的落地结果）

- 消息条数上限 **200 条**（`SubtitleCaptionBuffer.DefaultCapacity`），超出丢弃最旧的，内存有界；
- 暂停后重新开始**接着已有消息继续追加**：`Pause` / `Resume` 只控制是否追加，不清空、不改写已有消息；
- 自动滚底只在用户停留在底部时生效；用户上翻后改为显示「有新消息」提示，回到底部再恢复自动滚动；
- 呈现内容「仅译文 / 译文 + 原文」在语音页「字幕窗口」卡片内切换，落在 `v2-voice-settings.json` 的 `SubtitleContent`，默认「译文 + 原文」。

- **测试素材**：B 站视频 <https://www.bilibili.com/video/BV1dEY76fEn2/> —— 用户指定的音频测试素材，本现象即由此发现。

## D2 · 术语库卡片前端细节

- **状态：已实施**（保存按钮与重复的「启用」文字已删除、标题行与其它卡片对齐；删除按钮后缺失的自动保存触发点已补齐）
- **现象与要求**（用户提供了截图）：
  1. **删除「保存」按钮**：术语表是自动保存的，这个按钮多余且误导；
  2. **删除「启用」文字**：开关本身已有「开 / 关」提示，重复；
  3. **标题与控件对齐**：术语库卡片的标题、开关、表头等对齐需要统一（与其它卡片的对齐规范一致）。
- **影响面**：翻译页术语库卡片（XAML 为主 + 少量 code-behind 事件解绑），**不涉及术语表存储与匹配逻辑**。
- **注意**：删除「保存」按钮后要确认自动保存的触发点覆盖原有的手动保存语义（增删改术语后立即落盘），避免改出"看起来保存了其实没落盘"。
- **落盘验证**：实施时发现原实现只有「保存」按钮会写 `glossary.json`，新增 / 删除 / 开关都只改内存列表；现已把 `PersistGlossaryAsync` 接到添加、删除、启用开关三处，并在 `tests/Invoke-V2Validation.ps1` 的翻译页交互冒烟里用一次性术语实测：修改 → 文件出现探针值、新增 → 文件出现新词条、删除 → 探针值消失、开关 → `enabled` 翻转，验证后恢复原文件。

## D3 · 「字幕」快捷键的名称与实际职责不符；并取消暂停识别

- **状态：待排期（本次仅记录，未实施）**
- **现状**：F7 目前**只**切换字幕浮窗的显示/隐藏，不影响他人语音识别（识别由语音页的开始/停止按钮控制）。
- **要求（用户已澄清）**：
  1. **让 F7 同时开关语音识别**：按下时“开”＝开始他人语音识别 + 显示字幕浮窗；再按下“关”＝停止识别 + 隐藏浮窗。
     即这条快捷键成为整个“他人语音 → 字幕”功能的总开关。
  2. **改名**：它的职责从“只管子幕”变成“识别 + 字幕”，所以不能再叫「字幕」。
  3. **不新增快捷键**：不要为“暂停识别”单独加一条，一切合并在这一条上。
- **名称已定：`他人语音`**（与侧边栏页面名「语音」呼应；设置页三行成为「打开输入框 / 他人语音 / 自身语音」）。
  所有出现该快捷键的地方统一为「他人语音」，提示语改为“开始 / 停止他人语音识别”。
- **影响面**：设置页快捷键行文案与提示语（现为“打开 / 关闭字幕”）、指南页快捷键表、语音页与浮窗的快捷键提示、
  F7 的行为接线（`HotkeyActionRouter` / `MainWindow` / `VoiceSessionHost` 的启停路径）；**不涉及识别模型与翻译逻辑**。
- **行为后果与决定（用户已裁定）**：
  - F7 成为“全开 / 全关”：开启＝开始识别 + 显示浮窗，关闭＝停止识别 + 隐藏浮窗；
  - **删除语音页上的「打开字幕」按钮**（用户不认同保留“只藏窗口”的入口）：浮窗只随识别状态出现与消失，
    不再提供独立开关。实施时须同步更新验证脚本中与之相关的断言与冒烟（例如“打开字幕 只允许出现一次”的计数断言、
    以及用该按钮打开浮窗的冒烟路径），按新交互保留其真实意图，不得为了通过而放宽要求；
  - 识别启动需要模型就绪：模型未就绪时按 F7 应给一次明确提示（而不是静默无反应）；
  - 浮窗隐藏与识别停止必须走同一条串行化路径，避免“窗口藏了但识别还在跑”或反之的中间态。


## D4 · 字幕浮窗的「麦克风」标识易误会；字幕应水平居中

- **状态：实施中（与 D3 一并执行）**
- **现象与要求**：
  1. 字幕浮窗左侧有一个圆形标识，看起来像**麦克风**，容易让人误会“软件在用麦克风收音”——实际采集的是系统声音 / VRChat 音频。**去掉该标识**；
  2. 字幕文本改为**水平居中**。
- **影响面**：`SubtitleOverlayWindow.xaml` / `.xaml.cs`。
- **连带影响（实施时必须处理）**：该标识就是“活动标记”（subtitle-activity-mark），`Invoke-V2Validation.ps1` 里有一条
  「Subtitle activity mark render and animation」冒烟专门统计它区域的像素变化。标识移除后必须同步更新该冒烟与相关断言，
  按新的真实意图处理（浮窗不再有活动指示），不得为了让脚本通过而放水；活动反馈仍由语音页的电平表承担。
