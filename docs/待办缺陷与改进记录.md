# 待办缺陷与改进记录

用户确认后才执行。每条记录现象、影响、方向与状态；标注「待排期」的条目**不实现**。

## D1 · 他人语音长对话消息堆叠，无法查阅

- **状态：已实施**（消息条滚动列表：每条一句、可上下回看、新消息自动滚到底；不持久化、无清空入口；暂停保持现状）
- **现象**：语速很快的长对话里，字幕把连续多句一次性堆在一起输出，成了一整块文字，无法逐条查阅。
- **期望**：改成消息条滚动列表（类似 QQ / 微信）——每条一句、可上下滚动回看历史、新消息自动滚到底。
- **影响面**：只涉及字幕的呈现与消息模型（`SubtitleOverlayWindow` / `OverlayWindowHost` / `SubtitleSpeechSession` 的输出路径），**不涉及识别与翻译链路**。

### 已确认的产品决定

| 问题 | 决定 |
| --- | --- |
| 是否持久化历史 | **不持久化**：消息只存在于当前运行期间，不写磁盘 |
| 是否提供「清空」 | **不提供**清空按钮 |
| 暂停时的行为 | **保持现状**：暂停即停止追加，不清空、不改变已有消息 |
| 与现有「原文 + 译文」结构 | **合并为同一条消息**，不新增一层结构 |
| 呈现内容 | **可选**：仅译文 / 译文 + 原文 |
| 说话人标签 | 开启说话人区分时随消息呈现（沿用现有标签） |

### 实施决定（原「待定」项的落地结果）

- 消息条数上限 **200 条**（`SubtitleCaptionBuffer.DefaultCapacity`），超出丢弃最旧的，内存有界；
- 暂停后重新开始**接着已有消息继续追加**：`Pause` / `Resume` 只控制是否追加，不清空、不改写已有消息；
- 自动滚底只在用户停留在底部时生效；用户上翻后改为显示「有新消息」提示，回到底部再恢复自动滚动；
- 呈现内容「仅译文 / 译文 + 原文」在语音页「字幕窗口」卡片内切换，落在 `v2-voice-settings.json` 的 `SubtitleContent`，默认「译文 + 原文」。

- **测试素材**：B 站视频 <https://www.bilibili.com/video/BV1dEY76fEn2/> —— 用户指定的音频测试素材，本现象即由此发现。

## D2 · 术语库卡片前端细节

- **状态：已实施**（保存按钮与重复的「启用」文字已删除、标题行与其它卡片对齐；删除按钮后缺失的自动保存触发点已补齐）
- **现象与要求**（用户提供了截图）：
  1. **删除「保存」按钮**：术语表是自动保存的，这个按钮多余且误导；
  2. **删除「启用」文字**：开关本身已有「开 / 关」提示，重复；
  3. **标题与控件对齐**：术语库卡片的标题、开关、表头等对齐需要统一（与其它卡片的对齐规范一致）。
- **影响面**：翻译页术语库卡片（XAML 为主 + 少量 code-behind 事件解绑），**不涉及术语表存储与匹配逻辑**。
- **注意**：删除「保存」按钮后要确认自动保存的触发点覆盖原有的手动保存语义（增删改术语后立即落盘），避免改出"看起来保存了其实没落盘"。
- **落盘验证**：实施时发现原实现只有「保存」按钮会写 `glossary.json`，新增 / 删除 / 开关都只改内存列表；现已把 `PersistGlossaryAsync` 接到添加、删除、启用开关三处，并在 `tests/Invoke-V2Validation.ps1` 的翻译页交互冒烟里用一次性术语实测：修改 → 文件出现探针值、新增 → 文件出现新词条、删除 → 探针值消失、开关 → `enabled` 翻转，验证后恢复原文件。

## D3 · 「字幕」快捷键的名称与实际职责不符；并取消暂停识别

- **状态：已实施**（与 D4 一并执行；F7 成为「他人语音 → 字幕」总开关，语音页「打开字幕」按钮已删除）
- **现状**：F7 目前**只**切换字幕浮窗的显示/隐藏，不影响他人语音识别（识别由语音页的开始/停止按钮控制）。
- **要求（用户已澄清）**：
  1. **让 F7 同时开关语音识别**：按下时“开”＝开始他人语音识别 + 显示字幕浮窗；再按下“关”＝停止识别 + 隐藏浮窗。
     即这条快捷键成为整个“他人语音 → 字幕”功能的总开关。
  2. **改名**：它的职责从“只管子幕”变成“识别 + 字幕”，所以不能再叫「字幕」。
  3. **不新增快捷键**：不要为“暂停识别”单独加一条，一切合并在这一条上。
- **名称已定：`他人语音`**（与侧边栏页面名「语音」呼应；设置页三行成为「打开输入框 / 他人语音 / 自身语音」）。
  所有出现该快捷键的地方统一为「他人语音」，提示语改为“开始 / 停止他人语音识别”。
- **影响面**：设置页快捷键行文案与提示语（现为“打开 / 关闭字幕”）、指南页快捷键表、语音页与浮窗的快捷键提示、
  F7 的行为接线（`HotkeyActionRouter` / `MainWindow` / `VoiceSessionHost` 的启停路径）；**不涉及识别模型与翻译逻辑**。
- **行为后果与决定（用户已裁定）**：
  - F7 成为“全开 / 全关”：开启＝开始识别 + 显示浮窗，关闭＝停止识别 + 隐藏浮窗；
  - **删除语音页上的「打开字幕」按钮**（用户不认同保留“只藏窗口”的入口）：浮窗只随识别状态出现与消失，
    不再提供独立开关。实施时须同步更新验证脚本中与之相关的断言与冒烟（例如“打开字幕 只允许出现一次”的计数断言、
    以及用该按钮打开浮窗的冒烟路径），按新交互保留其真实意图，不得为了通过而放宽要求；
  - 识别启动需要模型就绪：模型未就绪时按 F7 应给一次明确提示（而不是静默无反应）；
  - 浮窗隐藏与识别停止必须走同一条串行化路径，避免“窗口藏了但识别还在跑”或反之的中间态。

### 实施结果

- **总开关**：Application 层的 OtherPlayerCaptionToggle 是唯一入口——快捷键、语音页的开始 / 停止按钮、
  以及字幕浮窗的系统关闭都走它；切换在信号量上串行化，开＝先启动识别再显示浮窗，
  关＝先停止识别再隐藏浮窗（停止报错也会把浮窗收掉），模型未就绪时两个效果都不施加。
- **窗口与识别不会脱节**：OverlayWindowHost 同时把 SubtitleVoice.RunningChanged 映射到浮窗的显示 / 隐藏，
  因此任何启停路径（含退出时的 ShutdownSpeechAsync）结束时窗口状态都等于识别状态；
  关闭字幕窗口不再是“只藏窗口”，而是把整条功能关掉（停止识别 + 隐藏窗口）。
- **启动行为**：字幕浮窗不再随程序启动出现，只在识别运行时出现——识别没跑时它不留在桌面上。
- **模型未就绪**：按 F7 会切到语音页并弹出一条明确提示（“本地语音模型尚未就绪，请先安装模型”），
  不再静默无反应；判定与提示都落在可测接缝上（OtherPlayerCaptionToggleOutcome.ModelNotReady）。
- **改名**：设置页快捷键行、指南页快捷键表、语音页快捷键提示统一为「他人语音」，
  提示语为“开始 / 停止他人语音识别”（设置页三行为「打开输入框 / 他人语音 / 自身语音」）。
- **验证脚本**：删除「打开字幕 只允许出现一次」的计数断言与该按钮的交互冒烟，改为断言按钮必须不存在、
  语音页唯一入口走总开关；语音页冒烟改用 F7 打开 / 关闭浮窗，并用状态文本核对“窗口可见 ⇔ 识别运行”。


## D4 · 字幕浮窗的「麦克风」标识易误会；字幕应水平居中

- **状态：已实施**（与 D3 一并执行）
- **现象与要求**：
  1. 字幕浮窗左侧有一个圆形标识，看起来像**麦克风**，容易让人误会“软件在用麦克风收音”——实际采集的是系统声音 / VRChat 音频。**去掉该标识**；
  2. 字幕文本改为**水平居中**。
- **影响面**：`SubtitleOverlayWindow.xaml` / `.xaml.cs`。
- **连带影响（实施时必须处理）**：该标识就是“活动标记”（subtitle-activity-mark），`Invoke-V2Validation.ps1` 里有一条
  「Subtitle activity mark render and animation」冒烟专门统计它区域的像素变化。标识移除后必须同步更新该冒烟与相关断言，
  按新的真实意图处理（浮窗不再有活动指示），不得为了让脚本通过而放水；活动反馈仍由语音页的电平表承担。

### 实施结果

- 左侧圆形活动标识（含呼吸光环与 90ms 视觉定时器）已整体删除，浮窗只剩消息条与「有新消息」提示；
  源码断言改为“不得再出现活动标识 / 图标 / 装饰”，渲染冒烟改为核对表面已绘制、没有残留强调色像素，
  并核对消息条在浮窗内左右留白对称（旧标识列会让左侧多出 46px）。
- 消息条、译文、原文与说话人标签行全部按整条消息宽度居中（TextAlignment.Center + 拉伸），
  D1 的消息条列表、自动滚底与上翻提示行为不变。

## D5 · 他人语音的译文漏进「输入框」（已修复）

- **现象**：识别他人语音时，翻译结果同时出现在**快速输入浮窗**里（那是给自己说话用的）。
- **根因**：`VoiceSessionHost.SubtitleSpeechSession` 把他人语音的译文写进了**共享的翻译预览状态** `AppState.SetTranslationPreview`，
  而 `QuickInputWindow` 与自身语音页都订阅 `TranslationPreviewChanged`。等于把“别人说的话”塞进了“我说的话”的展示位。
- **修复**：他人语音路径不再写共享预览；字幕只走字幕浮窗（OSC 行保持原样）。自身语音路径不变。

## D6 · 字幕浮窗样式问题与渐进式字幕（已实施）

- **状态：已实施**（样式改造与渐进式字幕均已落地，见文末「实施结果」）
- **用户反馈（原话要点）**：字太大；句子和译文的格式不统一；第一句译文的位置不对；有时候一次弹出两个翻译记录；整体看着不舒服。
- **现状实测（代码事实）**：
  - 译文 22px / SemiBold，原文 15px / Normal，说话人标签 12px / SemiBold；三者全部**居中**；
  - 每条消息是一个**圆角气泡**（Background + CornerRadius 8 + Padding 10,6 + 下间距 6）；
  - 浮窗最小宽度仅 360px —— 在这么窄的窗口里放 22px 译文，一句话会被拆成很多行，这是“字太大”的量化原因；
  - 消息列表 `VerticalAlignment=Bottom`（底部对齐）：只有一条消息时它贴在窗口最底部，上方全空 —— 这很可能就是“第一句位置不对”的观感来源。
- **“一次弹出两条”的两种可能（需确认）**：① VAD 把一句话切成两段，各自成条（Silero VAD 上线后更敏感）；
  ② 同一条消息被渲染两次。需要用户提供一张截图（或说明两条内容是否重复）来定位。

### 改造方案（待确认）

| 项 | 现状 | 建议 |
| --- | --- | --- |
| 译文字号 | 22px | **18px**（并可随窗口宽度自适应，窄窗再降一档） |
| 原文字号 | 15px | **13px**，颜色再暗一档，明确是“辅助信息” |
| 统一格式 | 译文 SemiBold 居中 + 原文 Normal 居中，主次差异过大 | 两者**同一对齐方式、同一左右内边距、同一行距**；只用字号/字重/颜色区分主次 |
| 行序 | 按消息内容顺序（译文在前、原文在后） | 固定为**译文在上、原文在下**（同一条消息内），不要随来源变化 |
| 气泡 | 每条一个圆角气泡 | 保留消息条概念，但**去掉圆角气泡感**：整块深色表面 + 细分隔（更像播放器字幕，减少视觉噪音） |
| 首条位置 | 底部对齐，单条时贴底、上方大片留白 | 保持底部对齐（字幕惯例），但**窗口高度随内容收缩到合适值**，避免单条时窗口空一大块 |
| 间距 | 消息间 6px，气泡内 10,6 | 行距 1.35 左右，消息间 8~10px，视觉上更透气 |

- **“参考他人做法”的结论**：主流字幕（YouTube 双语、会议字幕）是**居中、无气泡、半透明深色底、主译文大 + 副原文小、字号随窗口自适应**；
  QQ/微信式气泡适合聊天记录，用在实时字幕上会显得碎、吵。建议按上表向“播放器字幕”靠，同时保留可回看滚动。


### D6 决定（已确认）

- **样式方向：认可**，按上表实施（译文 18px、原文 13px、统一格式、固定“译文在上原文在下”、弱化气泡向播放器字幕靠、窗口高度随内容收缩、行距 1.35 / 消息间距 8~10px）。
- **“一次弹出两条”的成因已查明（用户确认）**：**内容不重复**，是 VAD 把快语速切成了两段，加上翻译（约 900 ms）远慢于识别（约 140 ms），
  第二段识别完成时第一段还在翻译，于是两条译文几乎同时落地。既有“分段”因素也有“翻译慢”因素，不是渲染重复。
- **采用的对策：渐进式字幕**——识别完成即先显示原文（含说话人标签），译文到达后再**填进同一条消息**，不改条数、不重排。
  这样每条消息在它真正识别出来时就出现，翻译只是后续填充，不再出现“一次冒出两条”。
  （VAD 阈值在无实测证据前不动；如仍嫌切得碎，另行评估。）

### 实施结果

- **样式**（`SubtitleOverlayWindow.xaml.cs`）：译文 18px、窄窗（面板宽度 < 420）降一档到 16px；原文 13px 且颜色调暗一档（#93A7BC）；
  说话人 12px。三行共用同一居中方式（`TextAlignment.Center` + 整条宽度拉伸）、同一左右内边距（12）与同一行距（1.35 × 字号）。
  行序固定「译文在上、原文在下」，由 `SubtitleCaptionBuffer.Present` 一处决定，不随来源变化。
- **气泡**：删除每条消息的圆角气泡与底色，改成整块深色表面 + 消息之间的 1px 细分隔（#26364B），消息间距 9px；
  最上面那条不画分隔线（`RefreshSeparators`）。浮窗仍然没有选择器、没有清空入口、只有一个 `subtitle-text`，XAML 里只剩「有新消息」一个 Button。
- **窗口高度随内容收缩**：`FitSurfaceHeight` 按消息列表的实际高度 + 非客户区高度算出目标高度（下限是面板最小高度 `MinHeight=72`），
  底部边缘固定（由 `OverlayWindowController.ResizeKeepingBottom` 向上生长），不超过用户上次的窗口高度，
  单条消息不再贴在一个大空块的最下面。
  - 还没有任何消息时不做收缩：空面板保持用户留下的矩形，不为「零条消息」先塌成一条。
  - 用户手动改过窗口高度后，本次运行不再随内容改高度（`_readerOwnsHeight`），不会把刚拖出来的高度又缩回去。
    用户的高度同时是上限与持久化目标：`ToStoredLayout` 只存「用户高度 + 保持底边」，
    自动跟随出来的高度是运行时细节，既不会覆盖用户的选择，也不会让下一次启动被压缩后的高度卡住。
- **渐进式字幕**：`VoiceSessionHost` 新增 `PublishRecognized` 钩子，在结果排队等翻译之前就把它交给浮窗；
  浮窗用调用方给的关联 id 建一条「只有原文 + 说话人标签」的消息（`SubtitleCaption.Pending`），
  翻译完成后用同一个 id 调 `SubtitleCaptionBuffer.TrySetTranslation`，只重绘这一条（不新增、不重排、不改变滚动位置）。
- **失败与空译文**：翻译抛异常或返回空串时，该条解析成 `SubtitleTranslationState.Unavailable`，
  仍是只有原文的一条消息，行尾标注「（未翻译）」，不会留下永远空着的占位，也不会永远停在「等待翻译」。
- **既有行为不变**：200 条上限与丢弃最旧、暂停保持（暂停只挡新消息，已经显示出来的那条仍会被填完）、
  上翻不被拉回、「有新消息」提示、仅译文 / 译文 + 原文模式、OSC 行仍只发译文且照旧走 `TranslationOutputFormatter.TrimForOsc`。
  「仅译文」模式下译文未到达时显示原文，到达后原地换成译文（同一条消息）。
- **测试**：`SubtitleCaptionBufferTests` 新增 10 个渐进式用例（先出原文、译文填进同一条且条数不变、空/失败解析、仅译文过渡显示、
  未知 id 不动已有消息、按 id 读回、暂停中仍然完成、超出上限的待填消息不再可填）；`Invoke-V2Validation.ps1` 增加 D6 源断言
  （样式常量、无 `CornerRadius`、细分隔、随内容高度、渐进式链路、浮窗仍然只有一个 Button、失败必须解析而不是留占位）。
