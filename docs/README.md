## 2. ⚠️ 测试口径时间线（**看数据前必读**）

同一个指标在不同文档里数字不同，多半是**口径不同**，不是谁写错了。按时间顺序：

| 时间 | 文档 | 实测对象 | 口径（关键差异） | 当时的结论 |
| --- | --- | --- | --- | --- |
| 2026-07-21 | `archive/多语言全链路质量与性能测试报告.md` | V1（v0.10.0，**含 OCR**、Python 脚本） | 九语言 OCR + 八种口语 ASR + 三个付费翻译档案；**OCR 已不在 V2 范围** | 中英日韩用 SenseVoice；16px 中文/韩文 OCR 差；需通用不变量保护 |
| 2026-09 | `archive/DeepSeek翻译实测.md` | 直连 DeepSeek API（**脚本**，非软件） | **单次调用、单一目标语言、不含 VAD、不含 OSC 发送**；系统提示是旧版（无源语言声明） | 中位约 900 ms；思考模式不值得开（慢 2.3 倍、输出 tokens 20~25 倍） |
| 2026-09-15 | [翻译服务软件内实测对比.md](翻译服务软件内实测对比.md) | **软件内**（UI Automation 驱动真实进程） | **按 Enter → 收到 OSC 报文**；每句**两个目标语言**（英语+日语）；含 VAD 之外的整条链路 | DeepSeek 1590 ms、小米 2553 ms（**含"两次串行"的放大**） |
| 2026-09-15 夜 | 同上 §5.1(5) / `archive/并行翻译实施方案.md` | 同上，**并行化之后** | 同上，但两个目标并发 | **DeepSeek 1031 ms（-35%）、小米 1356 ms（-47%）** |
| 2026-09-16 | [实验报告-识别与翻译.md](实验报告-识别与翻译.md) | **他人语音链路**：内置 SenseVoice + 5 个 provider（反射直调，不经 UI） | **识别与翻译分开计时**；翻译延迟＝单次 HTTP 调用（不含 VAD、不含 OSC）；质量＝对人工参考译文的 chrF2/BLEU-4；27 条 × 5 引擎 × 4 轮交错调用 + Wilcoxon 检验 | 机翻 195~269 ms、大模型 495~696 ms；纯中文/粤语应跳过翻译；同时讲话无法识别（单说话人模型上限） |

**一句话记法**：

- 旧文的 ~900 ms ＝ **模型单次调用**；
- 新文的 1590 → 1031 ms ＝ **用户按 Enter 到 VRChat 收到消息**（含两次调用、含发送）；
- 两者**不能直接比大小**，只能各自在"同一口径内"比（例如 DeepSeek 1590 → 1031 是同一口径的改进）。

**语音（自身语音）还要多一段**：VAD 判定"说完了"要等 **600 ms 静音**（`SileroVadSegmenter`），
所以"说完话 → 字幕出现" ≈ 0.6 s(VAD) + 0.14 s(识别) + 翻译时间。

### 3.1 发布手测包的两条硬要求（踩过坑）

1. **必须清空输出目录再发布**，否则会混进上一次的产物：
   ```powershell
   Remove-Item -Recurse -Force artifacts\manual-test
   dotnet publish src/VrcTranslate.Desktop/VrcTranslate.Desktop.csproj -c Release `
     -p:Platform=x64 -r win-x64 --self-contained true -o artifacts/manual-test
   ```
   症状：`dotnet publish -o` **不会清空**目标目录，一次不带 `--self-contained` 的发布会把
   **框架依赖版**的 `VrcTranslate.runtimeconfig.json` 留在里面，和自包含的 `coreclr.dll` 混在一起。
   双击 exe 就会弹「You must install or update .NET to run this application」——
   即使机器上装了 .NET 10 也一样，因为 apphost 按 runtimeconfig 去找运行时。
   **自检**：干净的包，`VrcTranslate.runtimeconfig.json` 里应该是 `includedFrameworks`（带着版本号），
   **不是** `framework`。
2. **发布后必须重铺 `data` 目录**（档案/密钥都在里面，发布不会带走）：
   ```powershell
   pwsh -NoProfile -ExecutionPolicy Bypass -File artifacts\seed-profiles.ps1
   ```
   该脚本会在 `artifacts\profile-backup\` 留一份备份，密钥来源按"备份 → 包内 → 用户目录"回退；
   任何一家缺密钥都会**明确报错而不是写半份档案**。
   另外**发布前先关掉正在运行的软件**，否则文件被占用会导致发布失败（exe 保持旧时间戳）。
