# 语音漏识别优化方案

## 现状与根因分析

当前链路：WASAPI 采集（回环/麦克风）→ `SpeechSegmenter`（RMS 能量门限切句）→ SenseVoice 离线识别 → 翻译 → OSC 字幕。

`SpeechSegmenter` 的判定逻辑（`src/VrcTranslate.Application/Speech/SpeechSegmenter.cs`）：

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| energyThreshold | **0.012（写死）** | 20ms 窗口 RMS ≥ 阈值即视为"有人说话" |
| 预滚 | 200ms | 起说话前保留的音频 |
| 静音收尾 | 520ms | 连续静音超过即切出一段 |
| 最长段 | 8s | 超长强制切段 |
| 空结果 | 直接丢弃 | 识别返回空文本时不产生任何输出 |

**漏识别的四个根因：**

1. **固定能量门限不适配真实环境（主因）**
   - VRChat 回环音频 = 人声 + 游戏 BGM/音效。BGM 稍大时环境 RMS 长期 ≥ 0.012 → `_hasSpeech` 永不回落 → 说话内容混在 8 秒噪声段里送识别，SenseVoice 返回空文本被静默丢弃 → 用户感觉"整句漏了"。
   - 反过来，说话声音小 / 麦克风增益低（自身语音路径）时 RMS 始终 < 0.012 → 完全不触发切句 → 一个字都出不来。
   - 一个固定阈值不可能同时适应"游戏背景音"和"安静麦克风"两个方向。

2. **词首裁剪**：预滚只有 200ms，且以"20ms 窗口过阈值"为起点；轻声起音/拖长音节的开头落在预滚之外，送识别时句首丢字。

3. **静音判定同样基于绝对阈值**：说话人语间停顿、BGM 抬底，都会让 520ms 计时失真 → 该切不切（内容被并进前一段、延迟 8s 才出）或不该切却切了。

4. **空结果静默丢弃**：识别失败/纯噪声段返回空文本直接 `continue`，无日志无计数，漏了也不知道漏在哪一环。

## 方案（两个阶段，同一目标：把"能量门限"换成"噪声自适应 + 语义级 VAD"）

### 阶段 1：噪声自适应能量门限 + 可观测性（先做，1 天）

不引入新依赖，改造 `SpeechSegmenter`：

1. **自适应噪声底**：维护滑动 2s 窗口的 RMS 低分位（min-statistics：每 100ms 记录一次窗口 RMS，取近 2s 的 10% 分位作为噪声底 `noiseFloor`，EMA 平滑）。判活阈值动态化为 `max(0.006, noiseFloor × 4)`，并设上限 0.05。
   - BGM 大 → 阈值自动抬高，人声仍需明显高于底噪才触发，避免全程误判"在说话"。
   - 安静麦克风 → 阈值降到 0.006 下限，小音量也能触发。
2. **静音判定相对化**：段内静音 = RMS < noiseFloor × 2.5（而不是绝对 0.012），收尾延时 520ms → 600ms，减少语间停顿被腰斩。
3. **预滚加长**：200ms → 320ms（约 5120 样本），起音更完整。
4. **最小段长**：新参数 minSpeechMilliseconds=240，短于 240ms 的激活段视为点击/瞬态噪声丢弃（防止阈值降低后误触发垃圾段）。
5. **诊断计数**：`SpeechSegmenter` 暴露 `Diagnostics`（段总数、空文本段数、当前噪声底、激活占比）；`LocalSpeechCaptureSession` 汇总后在停止时输出一行摘要日志。调参有据可依。

阶段 1 验收：合成信号单测（干净人声、人声+10dB/6dB BGM、小音量人声 RMS≈0.005、慢起音、语间停顿 700ms、纯 BGM 不出段）+ 你在 VRChat 实测 15 分钟主观漏识别率。

### 阶段 2：Silero VAD 替换能量门限（根治，1.5~2 天）

能量门限原理上分不清"游戏音效"和"人声"。sherpa-onnx 自带 Silero VAD（已在引用的 `org.k2fsa.sherpa.onnx` 1.13.8 中确认存在 `SileroVad` / `SileroVadModelConfig` API），模型仅约 2.2MB，CPU 单帧推理 <1ms，是业界标准方案。

1. **引入模型**：下载 `silero_vad.onnx` 放入 `assets/models/`，随程序内置（体积代价 ~2.2MB）。
2. **新增 `VadSpeechSegmenter`**（与 `SpeechSegmenter` 同接口 `Append/Flush`）：
   - 用 `SileroVad` 逐窗输出语音概率（窗 32ms/步长 32ms）；
   - 迟滞判定：概率 ≥0.5 开段、≤0.35 关段（+600ms hangover 收尾）；
   - 保留阶段 1 的预滚、最小段长、最长段（8s→12s）、Flush 逻辑；
   - 识别器输入仍是完整段，SenseVoice 侧零改动。
3. **降级链**：VAD 模型加载失败时自动回退阶段 1 的自适应能量门限，功能不中断。
4. **配置**：设置页不动，内部默认启用 VAD；后续如需暴露开关再加。

阶段 2 验收：同一组合成信号回归 + 纯 BGM/枪声/脚步声 30 分钟不出垃圾段 + VRChat 实测；与阶段 1 对比空文本段数量应下降一个量级。

### 不做的事

- 不动 SenseVoice 模型与识别参数（漏识别的瓶颈在"送进去的音频就不对"，不在模型）。
- 不做回声消除/AEC（VRChat 回环里自己游戏声音与人声混合的问题，VAD+相对阈值已能显著缓解，Acer 代价新增 DSP 链路暂不值得）。
- 暂不接云端 ASR 兜底（与"全面本地化"的既定决策冲突，先看本地效果）。

## 实施记录

- 2026-09-15：两个阶段已全部实施。阶段 1 见 `SpeechSegmenter`（自适应噪声底 + 迟滞门限 + 320ms 预滚 + 240ms 最小段长 + 诊断计数，停止时经 Debug 输出摘要）；阶段 2 见 `SileroVadSegmenter` / `LocalSpeechSegmenterFactory`（silero_vad.onnx 630KB 随包内置于 `Models\vad`，加载失败自动回退能量门限）。导入脚本已支持 VAD 模型（GitHub 源 + SHA-256 校验）。单测 174 个全绿；实测项待 VRChat 环境验证。
