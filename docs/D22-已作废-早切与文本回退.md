# D22：早切 + 文本回退 —— ❌ 可行性验证未通过，已作废

> **状态：作废（2026-09-16）**。原因见 §0——D22-0 的实测把这个方案的前提直接否掉了。
> 保留本文是为了**留下「为什么不做」的证据**，避免以后有人再提一次。

## 0. 结论：SenseVoice 只给整段末尾加一个标点

D22 的核心假设是「**识别文本能告诉我们句子说完了没有**」（末尾是句号＝说完了，逗号＝还没说完）。
D22-0 实测把这个假设推翻了。

### 实测（2026-09-16，素材：真实双人播客前 8 分钟 / 58 个 VAD 段）

| 指标 | 数值 |
| --- | ---: |
| 段尾是句子结束符（。？！?!.） | **57 / 58 段 = 98.3%** |
| **正文内部出现句子结束符的段** | **0 / 58 段 = 0.0%** |

**两个数字放一起就是结论**：SenseVoice 的输出是「**一整段串起来 + 末尾补一个标点**」，
**它不在句子之间断句**。于是：

1. 「末尾是句号 → 说完了」**永远成立**（98.3%）⇒ D22 的判定**永远走「立即上屏」**分支；
2. 「末尾是逗号 → 挂起等下一段」**几乎永不触发**（1.7%）⇒ **挂起与合并机制形同虚设**；
3. D22 于是**退化成「把静音阈值从 600 换成 250 ms」**——正是它本来要避免的那件事（会切错、会并错）。

### 跨语种复核（同样只有末尾一个标点）

| 语言 | 识别结果 | 标点数 |
| --- | --- | ---: |
| 中文 | 开饭时间早上9点至下午5点**。** | 1 |
| 日语 | うちの中学は弁当制で…パンを買う**。** | 1 |
| 韩语 | 조금만 생각을 하면서 살면 훨씬 편할 거야**.** | 1 |
| 英语 | The tribal chieftain called for the boy and presented him with 50 pieces of code**.** | 1 |
| 中文+日语拼接 | 开饭 うちの中学は…パンを買う**。** | 1 |

⇒ **不是英语特例，四种语言都一样**。

### 顺带解释了「文本大块大块」的来源

同一次实测还量到：播客里 **12~15 秒的长段，识别结果是一条 60~100 词的连续文本**，
语义上里面含 **3~5 个句子**，但**模型在中间不给任何标点**。
⇒ 「大块」不是翻译或显示的问题，是**模型输出本身没有段内结构**。

## 1. 原方案（存档）

静音 250 ms 就先切段识别，按末尾标点判断：句号则立即上屏，逗号则挂起、等下一段拼起来重识别。
其中「挂起 + 拼接重识别」是它相对「单纯降阈值」的唯一增量，**而该部分已被证明不会触发**。

## 2. 「说完话到字幕出现」还能压吗

| 手段 | 可行性 |
| --- | --- |
| 文本回退（本方案） | ❌ 前提不成立 |
| 单纯把静音阈值降到 250~400 ms | ⚠️ **可行但纯取舍**：说话人停顿区间重叠，会切错想词型、并错连说型；**没有任何智能补偿手段可用**（模型不给段内结构） |
| 句中节能（只在句中停顿 + 能量下落时早切） | ⚠️ 未验证；VAD 只有 0/1，能量判据可能与静音高度相关，收益存疑 |
| 换流式识别 | ✅ 唯一能同时要「快」和「准」的路，代价见《模型能力边界.md》§4 |

## 3. 建议

1. **D22 关闭**，不再实施；
2. 若用户愿意接受「偶尔切错/并错」，可把静音阈值 600 → **400 ms**（省 200 ms）——**纯调参，随时回滚**；
3. 想「连说型也快」只能走 D24（流式）。
