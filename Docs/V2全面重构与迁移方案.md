# VRCTranslate V2 全面重构与迁移方案

## 1. 结论

当前 V2 不能继续在现有页面上堆控件。需要把它定义为一次完整产品重构：先建立稳定的功能模型、配置模型和迁移契约，再重新设计 WinUI 前端，最后按功能垂直切片接入真实服务。

本方案不是对当前 V2 页面做局部美化，也不是只迁移大模型接口。旧版已有的快捷输入、OSC Chatbox、翻译档案、翻译路由、术语库、语音识别档案、VRChat 进程音频、字幕覆盖层、自身麦克风语音、托盘、全局热键和数据诊断都属于必须迁移的产品能力；配置迁移只作为升级维护工具的一次性工作，不作为用户功能。

OCR 暂不实现。产品中只保留一句指南说明：需要屏幕翻译时，可在 QQ 中按 `Ctrl+Alt+F`；其他软件的快捷键以其自身版本为准。VRCTranslate 暂不提供 OCR，后续是否增加集成能力将另行评估。

> **当前可测试边界**：当前用户入口固定为“运行 / 输入 / 字幕 / 翻译 / 设置 / 指南”，用户界面不提供旧版配置导入。输入和字幕均采用普通 Windows 窗口，标题分别为“输入”和“字幕”，由系统提供拖动、八方向缩放、光标、吸附、DPI 和多显示器行为。输入内容按简体中文处理；第一语言和可选第二语言只在“输入”页面配置，译文同时预览并发送。自身语音同样固定简体中文识别。其他语音使用可选的 C# Whisper Base Q5_1 本地模型，覆盖英语、日语、韩语，模型按需下载；字幕输出固定为简体中文，窗口内容不显示重复标题或语言选择。两个窗口的透明度可分别在对应页面调整为 60%～100%，默认 90%，位置、大小和透明度都会恢复。应用层已经接入麦克风与系统回环采集端口，桌面端目前捕获系统回环音频，VRChat 进程级过滤仍待完成，因此不能把所有系统声音误称为 VRChat 专属实时字幕。腾讯云、阿里云实时 ASR 不在当前用户入口中。

## 2. 当前问题判定

### 2.1 前端问题

- 当前导航栏使用默认 WinUI 外观，图标、选中态、文字对比度和应用品牌没有统一设计；窗口标题仍显示 `WinUI Desktop`。
- 页面把不同层级的内容都做成同样的白色卡片，没有工作区、状态区、配置区和高级区的区别。
- 页面标题、说明、表单、操作按钮和结果状态混在同一滚动流中，用户无法快速判断当前页面要解决什么问题。
- 现有页面只有静态配置壳，按钮没有对应的真实服务或状态事务，容易造成“看起来支持、实际不能用”。
- 快捷键出现在运行页、语音页、设置页和说明文字中，无法统一查看、修改和检测冲突。
- “开机自动启动”不属于当前产品需求，必须删除，不能作为默认设置出现。
- 颜色、字体、边框和间距没有形成设计令牌；浅色背景、浅色文字和默认控件组合导致低对比度及阅读疲劳。
- 当前界面没有清晰的动画反馈，例如启动、停止、连接测试、模型下载、识别中、字幕暂停和错误恢复。

### 2.2 功能迁移问题

旧版功能边界如下，V2 不能继续只做翻译模型配置：

- 输入与消息：普通 Windows 轻量输入窗口接收简体中文文字；在“输入”页面选择第一/第二输出语言，显示双译文并发送到 VRChat Chatbox（OSC），遵守发送节流和 144 UTF-16 单元限制。
- 翻译服务：测试回显、DeepL、Google Cloud、Google 免费接口、阿里云、腾讯云、OpenAI 兼容接口，以及服务档案的测试、超时、失败冷却和能力筛选。
- 翻译路由：输入文字和识别后的语音共用同一翻译服务；字幕固定输出简体中文，输入可在独立目标集合中配置第一语言和可选第二语言。内部路由保留源语言、目标语言、消息格式、超时、队列、TTL、罗马音和术语库策略，常用页面不暴露内部字段。
- 术语库：保留内置术语，支持用户添加、编辑和删除；导入/导出作为后续扩展。
- 字幕：目标固定为 VRChat，页面不提供进程选择；当前桌面端通过系统回环适配器接收音频，进程级过滤仍是后续工作。字幕输出固定简体中文，覆盖层不展示重复标题、目标语言或状态说明。
- 语音识别模型：V2 使用独立的本地 Whisper Base Q5_1 组件，提供安装、状态、删除和英语/日语/韩语能力；当前不提供腾讯云或阿里云实时 ASR 用户入口。
- 自身语音：当前提供麦克风选择与测试、启停快捷键、本地模型服务、固定简体中文识别、双目标翻译和 VRChat 发送；不能回退到 Windows SpeechRecognizer。
- 字幕覆盖层：内容区只显示译文和一个活动图标，不放重复标题、关闭按钮或语言选择；窗口使用系统标题栏和边框。系统关闭按钮仅隐藏窗口，快捷键再次打开时复用同一窗口；主程序退出时才销毁。目标语言固定为简体中文。
- OSC Chatbox：当前配置主机和端口；节流、提示音、typing 状态和消息分割作为内部策略或后续高级设置。
- 设置：当前提供快捷键和 OSC 连接；应用行为、便携数据目录、日志目录、缓存目录、日志清理和损坏配置恢复作为后续诊断入口。旧版配置迁移由维护工具一次性执行，不在用户界面提供导入入口。
- 托盘与全局热键：快捷输入、主窗口、语音状态、退出和热键冲突提示。

不迁移的能力：OCR 捕获、OCR 模型、OCR 调度、OCR 浮窗、OCR 嵌字和多模态图片 OCR。

## 3. 新的信息架构

主导航固定为六个入口，名称直接表达任务：

1. **运行**：显示当前翻译服务和模型，并进入三种输入方式。
2. **输入**：打开输入浮窗，查看翻译预览并发送到 VRChat。
3. **字幕**：启动/停止字幕并打开字幕窗口；音频目标固定为 VRChat。
4. **翻译**：管理翻译服务档案、统一路由和术语库。
5. **设置**：统一管理快捷键和 OSC 连接；数据目录和日志属于后续诊断入口。
6. **指南**：只放用户真正需要的操作说明和故障处理。

页面内部采用固定层级：

- 首屏：当前任务、状态、主操作。
- 常用配置：完成日常使用所需的最少选项。
- 高级配置：超时、队列、VAD、字幕细节等折叠显示。
- 诊断信息：只在错误、测试或用户主动打开时显示。

普通用户不需要看到内部的 provider id、任务 TTL、队列容量、坐标空间、捕获后端枚举和模型缓存细节。

## 4. 视觉和交互重做

### 4.1 视觉令牌

- 应用窗口标题统一为 `VRCTranslate`，不显示 `WinUI Desktop` 或阶段性的 `V2` 字样。
- 左侧导航使用深色品牌色背景，文字和图标使用高对比度；选中项使用明确的蓝色竖线和浅色底，不依赖低对比度灰色。
- 内容区使用浅灰背景，卡片仅用于独立任务模块；卡片不再层层嵌套。
- 主色只表达可操作控件和当前选中态；绿色只表示运行或验证成功；红色只表示错误；黄色表示需要处理。
- 标题、说明、标签、输入框和按钮使用统一字号层级，不再用超大标题占据首屏。
- 所有图标使用 Fluent/WinUI 图标资源，导航、发送、刷新、测试、日志、模型下载和状态都不能缺图标。

### 4.2 动画和状态

- 页面切换使用轻量淡入，不使用持续动画。
- 启动语音时显示“准备音频 → 识别中 → 翻译中 → 字幕显示”的状态变化。
- 停止时显示完成状态并收起字幕，不显示常驻悬浮球。
- 测试连接、模型安装和删除操作使用进度条、成功状态和失败原因。
- 所有异步操作都有取消入口，不允许按钮点击后无反馈。

### 4.3 快捷键统一入口

设置页增加唯一的“快捷键”区域，统一列出并编辑：

- 输入：默认 `Ctrl+Alt+I`。
- 语音字幕：默认 `F7`。
- 自身语音：默认 `Ctrl+F8`，默认关闭。

快捷键配置必须支持录入、冲突检测、恢复默认和保存状态。其他页面只显示“当前快捷键”摘要并提供跳转，不再重复编辑和解释。

### 4.4 输入与字幕窗口

两个游戏内窗口不再实现自绘窗框，也不再接管鼠标命中。统一采用 WinUI 3 `Window`、`AppWindow` 和 `OverlappedPresenter` 的普通重叠窗口：

- 标题分别固定为“输入”和“字幕”，保留系统标题栏、边框及窗口按钮；
- 拖动、八方向缩放、缩放光标、贴靠、多显示器和 DPI 切换全部交给 Windows；
- 不使用 `WM_NCHITTEST`、鼠标捕获、轮询移动、窗口区域裁剪或内容区模拟缩放边缘；
- 两个窗口保持置顶，但不启用鼠标穿透；
- 点击系统关闭按钮只隐藏窗口，快捷键再次打开时复用原窗口；关闭主程序时才真正销毁；
- 位置和大小由 `AppWindow.Changed` 记录，重新启动后恢复，并把失联显示器上的旧坐标纠正到可见工作区；
- 输入页和字幕页分别提供 60%～100% 的透明度滑杆，默认 90%，拖动即生效，无额外保存按钮；
- 整窗透明度由 Windows 顶层窗口统一应用，系统标题栏与内容同时变化，不使用 XAML 根元素 `Opacity` 叠加假透明。

透明度配置按分层边界实现：Core 定义数值范围，Application 管理当前快照和变更事件，Infrastructure 负责合并写入及原子替换，Desktop 只把设置应用到对应 HWND。输入与字幕各自保存，互不覆盖。

## 5. 设置模型和分层解耦

采用四层结构：

```text
VrcTranslate.Core
  业务实体、设置契约、路由规则、语言规则、不变量规则

VrcTranslate.Application
  翻译、语音、输入、OSC、内部迁移、诊断等用例和端口

VrcTranslate.Infrastructure
  JSON 配置、旧配置迁移、HTTP、OSC、系统音频采集、Whisper 本地模型、未来在线 ASR 适配、日志

VrcTranslate.Desktop
  WinUI 页面、ViewModel、导航、状态呈现和 Windows 平台适配
```

目标架构中 Desktop 不直接调用 HTTP、OSC 或音频代码，每个页面只依赖 Application 用例和可观察状态。当前手测包已把本地语音识别、分段和音频采集放在 Application/Infrastructure 端口后，Desktop 只管理会话生命周期和状态；OSC 与服务凭据下沉工作的剩余部分仍按发布门槛收尾。

设置根节点定义为：

```text
translation
  profiles
  default_route          # 文字输入和语音识别共用
  self_route             # 仅用于一次性迁移
  voice_route            # 仅用于一次性迁移
  glossary
voice
  asr_profiles
  vad
  overlay
self_voice
osc
system
diagnostics
```

正式发布时，配置中的密钥必须使用 Windows Credential Manager 或 DPAPI 保存，JSON 只保存凭据引用和服务档案元数据。当前手测包仍把部分服务凭据写入本机用户配置 JSON，只适合功能验证，不能视为该安全目标已经完成。

## 6. 语音识别模型方案

语音识别模型不是翻译模型，必须单独配置和显示状态。

### 当前状态与后续交付路径

当前可测试包使用可选的 Whisper Base Q5_1 本地语音模型，覆盖英语、日语、韩语；模型缺失时显示未安装，不调用系统 SpeechRecognizer。麦克风和系统回环采集已通过 NAudio 适配器接入应用会话，但回环目前没有 VRChat 进程级过滤。腾讯云和阿里云实时 ASR 不属于当前用户入口，后续适配前不应显示为可用。

模型文件按需下载到 `%LOCALAPPDATA%\VRCTranslate\v2\models\speech\ggml-base-q5_1.bin`，不写入发布目录；安装过程先写临时文件，完整校验后再替换正式文件。自身语音固定以简体中文识别；他人语音自动识别英语、日语或韩语，再固定翻译为简体中文。

1. 首次运行显示本地模型未安装状态，用户主动安装后才加载 Whisper 运行库。
2. 本地组件显示模型大小、安装状态、完整性状态和语言能力；安装失败不替换现有可用版本。
3. 完成 VRChat 进程级回环过滤，并用真实游戏音频验证误捕获和延迟。
4. 如重新引入腾讯云或阿里云实时 ASR，必须先完成真实连接测试，再单独设计凭据入口。
5. 模型安装、验证、删除都在语音字幕页或语音资源面板完成，不混入翻译模型表单。
6. 语音识别输出文本后，统一交给当前翻译路由；不能为语音再复制一套翻译服务配置。

### 识别配置简化

普通模式只显示：

- 音频来源：VRChat（应用内部固定目标；当前回环适配仍会接收系统混音，进程过滤完成前不宣称专属捕获）。
- 识别引擎：Whisper Base Q5_1 本地模型。
- 字幕窗口开关。

本地模型自动覆盖英语、日语、韩语；用户不需要在浮窗里重复配置源语言。字幕译文固定为简体中文。“输入”页面提供第一语言和可选第二语言，浮窗只保留文字输入和译文预览。

VAD、采样率、静音时长、最大分段长度、队列和识别超时属于后续的“高级语音设置”，提供“安静 / 平衡 / 嘈杂”预设。

## 7. 迁移策略

### 阶段 A：功能契约和内部一次性迁移

- 从旧版 `AppSettings` v13 固定所有字段和默认值。
- 为 v1-v13 配置迁移建立独立测试样本。
- 保留 provider-specific 凭据字段映射：腾讯的 `secret_id/secret_key`、阿里的 `access_key_id/access_key_secret`、语音服务的 `app_id/secret_id` 等。
- 支持损坏配置备份、原子替换和导入失败回滚。
- 迁移只由发布维护工具执行一次，不在 V2 用户界面提供“导入旧版配置”入口；V2 运行时不依赖 Python 配置代码。

### 阶段 B：工作区垂直切片

按以下顺序完成真实功能：

1. 输入浮窗 + OSC + 统一翻译路由。
2. 翻译服务档案和服务连接测试。
3. VRChat 进程音频采集和字幕覆盖层的实时接入（后续阶段；本地模型安装和状态已在 V2 完成）。
4. 腾讯/阿里在线 ASR 档案和连接测试（后续阶段）。
5. 完善自身麦克风语音并接入 VAD；不提供进程或激活范围配置。
6. 在现有术语添加/删除基础上补齐导入、编辑和导出。
7. 在现有全局热键基础上补齐托盘、日志和诊断。

每个阶段都必须同时包含 Core/Application 测试、Infrastructure 集成测试和 Desktop 页面启动冒烟。

### 阶段 C：替换旧项目

旧 Python/Qt 代码在 V2 完成验收前保留。V2 通过验收后：

- 先由维护工具导出旧版配置并生成备份。
- 用离线迁移工具转换配置；V2 用户界面不展示导入按钮。
- 保留旧版可执行文件一个版本周期。
- 确认用户数据、快捷键和服务档案可恢复后再删除旧运行入口。

## 8. 自动测试和手动测试门槛

每次交给用户手动测试前必须执行：

```powershell
dotnet build v2\VrcTranslate.sln -c Debug -p:Platform=x64
dotnet test v2\VrcTranslate.sln -c Debug -p:Platform=x64
v2\tests\Invoke-V2Validation.ps1
```

自动测试必须覆盖：

- 六个页面的 XAML 初始化和导航启动。
- 快捷输入、语音字幕、翻译服务和设置入口。
- 翻译路由的文字/语音复用。
- 服务档案和模型配置校验。
- 超时、重试、取消和不变量保护。
- OSC 分割、节流和 144 UTF-16 单元限制。
- ASR 本地模型缺失、安装失败、在线服务凭据缺失。
- 内部迁移工具的 v1-v13 配置映射和 provider-specific 凭据映射。
- 快捷键冲突和恢复默认。
- 配置损坏、备份和回滚。
- 输入和字幕窗口必须保留系统标题栏、边框、拖动与缩放能力，源码不得重新引入自定义命中或窗口区域裁剪。
- 两个窗口的透明度必须独立实时生效并跨进程恢复；默认 90%，越界配置归一化到 60%～100%。
- 点击浮窗的系统关闭按钮必须只隐藏并保留同一 HWND；关闭主程序必须销毁两个 HWND 并退出进程。
- 位置和大小必须在移动、缩放及进程重启后保持，输入编辑区必须随窗口变化并保持居中。

只有构建通过、自动测试全通过、六个页面冒烟通过，才提供新的 exe 给用户手动测试。

## 9. 验收标准

- 用户打开软件后 5 秒内知道“输入”和“字幕”分别做什么。
- 所有快捷键可以在一个入口查看和修改，其他页面只显示摘要。
