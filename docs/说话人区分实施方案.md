# 说话人区分与声纹命名实施方案

日期：2026-09-13。前置档案：《SenseVoice本地替换实施方案》§4、《语音识别方案选型》。阶段 1（SenseVoiceSmall INT8 全量替换）已实施并验收，本文档是阶段 2 的执行方案。

## 0. 决策记录

- **标签持久化 + 用户命名**：声纹库落盘，用户把「说话人A」改成玩家名后，同一声音在**下次会话自动沿用该名字**。早期「标签仅会话内有效、不做持久化」的结论作废。
- **未命名的说话人默认不落盘**：只有用户命名过的声纹进入声纹库，避免匿名声纹无限堆积；「自动记住未命名说话人」是默认关闭的高级开关。
- **双阈值**：会话内聚类宽松、跨会话重认从严。错认（把别人的话挂到「小明」名下）比漏认难看得多，宁可漏认。
- **引擎只用嵌入与分割**：`SpeakerEmbeddingExtractor` + `OfflineSpeakerDiarization`；登记表自研——引擎的 `SpeakerEmbeddingManager` 每个名字只存一个向量，满足不了质心、多样本与持久化。
- **换人切分按需触发**：先用「首尾嵌入相似度」做便宜判断，疑似换人才跑 pyannote 分割，避免每句都付分割成本（VRChat 同时占 CPU）。
- **模型按需下载，也能内置**：默认首次开启时从 hf-mirror 下载（约 30 MB）；`Import-BundledSpeechModel.ps1 -IncludeSpeaker` 可打进手测包。
- **声纹是生物特征**：仅存本机、可一键清空、不上传。

## 1. 目标与验收

| 项 | 指标 |
|---|---|
| 会话内聚类 | 脚本化双人对话（≥20 次换人）标签正确率 ≥90% |
| 换人切分 | 粘连句切分点误差 ≤300 ms、召回 ≥80%、误切 ≤10% |
| 跨会话重认 | 已命名说话人自动沿用率 ≥70%；**误认 ≤2%** |
| 单句开销 | 嵌入 + 匹配 P50 ≤30 ms（CPU，识别前串行执行） |
| 切分调用频率 | 平均 ≤1 次 / 10 句 |
| 内存增量 | ≤80 MiB（pyannote int8 1.5 MB + CAM++ 28.3 MB + 运行时） |
| 声纹库体积 | 单说话人 ≤8 KB（192 维 × 8 样本），20 人 ≤200 KB |
| 隐私 | 仅本地文件；未命名不落盘；可清空；不上传 |
| 回归 | 关闭开关时行为与阶段 1 完全一致；六页面、分层测试、验证脚本、发布冒烟全绿 |

## 2. 声纹库设计

### 2.1 文件

`%LOCALAPPDATA%\VRCTranslate\v2-speakers.json`，复用 `JsonConfigurationStore<T>` 的原子写与版本化。

```json
{
  "version": 1,
  "embeddingModel": "3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx",
  "dim": 192,
  "speakers": [
    {
      "id": "spk-7f3a91",
      "name": "小明",
      "createdAt": "2026-09-13T10:02:11Z",
      "lastSeenAt": "2026-09-13T10:41:03Z",
      "observationCount": 37,
      "centroid": [0.0131, -0.2402],
      "exemplars": [
        { "v": [0.0207, -0.1988], "at": "2026-09-13T10:41:03Z", "count": 12 }
      ]
    }
  ]
}
```

- `id` 与 `name` 分离：改名不动 id，字幕与日志引用 id。
- `centroid` 归一化存储；`exemplars` 最多 8 条，按 `count` 与时间做 LRU 淘汰（示例中向量截断为两位，实际写入完整维度）。
- 维度随模型走（读 `SpeakerEmbeddingExtractor.Dim`），不硬编码；`embeddingModel` 不一致时判定声纹库不可比，提示重建并备份旧文件——**不同嵌入模型的向量空间不可混用**。

### 2.2 匹配算法

```
e = normalize(embed(segment))
sim = max(cos(e, centroid), max_i cos(e, exemplar_i))     # 对本会话与声纹库的全体候选
best = argmax sim
threshold = best 来自声纹库 ? CrossSession : Session
sim >= threshold ? 命中 : 新建「说话人X」
```

- 起始值 `SessionThreshold = 0.50`、`CrossSessionThreshold = 0.65`（余弦），**必须按 §8 标定**，标定前按保守值发布。
- 命中后更新 `centroid = normalize((1-α)·centroid + α·e)`，`α = min(0.2, max(0.05, 1/(count+1)))`；只在该说话人未被用户改过名时更新，降低误匹配污染。
- 低置信度保护：`sim` 落在 `[threshold-0.05, threshold)` 且该句被判定为重叠语音时，沿用上一句标签且**不更新**声纹。

### 2.3 生命周期

| 事件 | 行为 |
|---|---|
| 用户命名「说话人A」→「小明」 | 该说话人写入声纹库（含质心与样本） |
| 用户改名 | 只改 `name`，声纹不动 |
| 用户合并 A→B | 样本合并、重算质心、删除 A |
| 用户「忘记」 | 删除该声纹条目 |
| 跨会话重认成功 | 更新 `lastSeenAt`、`observationCount`、EMA 质心与样本 |
| 长期未出现 | `lastSeenAt` 超过 30 天 → UI 标记「久未出现」，不自动删除 |

## 4. 单句处理流程

```
SpeechSegmenter 产出段
  1. 开关关闭 → 走阶段 1 原路径（零开销）
  2. 取段首 1.0 s 与段尾 1.0 s 的嵌入（段长 < 1.5 s 时只取整体）
  3. cos(首, 尾) < SplitThreshold(0.45) 且段长 >= 2 s → 疑似换人
       └─ 对该段跑 OfflineSpeakerDiarization.Process() → 按换人点切分（最多 3 段）
  4. 对每个片段取整体嵌入 → 注册表匹配 → 得到 SpeakerId
  5. 逐片段识别（复用阶段 1 的 SenseVoice 路径）
  6. 输出「名字：文本」，换人换色
```

成本：步骤 2 是两次短嵌入（每句约 +20~40 ms）；步骤 3 只对疑似句执行。步骤 2~4 与识别共用现有串行门控，不引入新的并发路径。

## 5. 用户界面

语音页新增「说话人」卡片（留在字幕页内，不新增页面）：

- 列表：显示名（点击重命名）、最后出现时间、出现次数、置信度提示。
- 行内操作：重命名 / 合并到… / 忘记 / 复制。
- 底部：说话人区分开关、「自动记住未命名说话人」（默认关）、清空声纹库（二次确认）。
- 字幕：未命名显示「说话人A/B/C」，命名后显示名字；同句多人时按切分结果逐段显示。
- 逆向纠错入口：字幕行右键/按钮「这不是小明」，把该句从该说话人剔除并降权对应样本。

## 6. 模型分发

| 模型 | 文件 | 体积 | 来源 |
|---|---|---|---|
| pyannote segmentation 3.0 | `model.int8.onnx` | 1.5 MB | `hf-mirror.com/csukuangfj/sherpa-onnx-pyannote-segmentation-3-0` |
| 3D-Speaker CAM++（zh+en） | `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` | 28.3 MB | `hf-mirror.com/csukuangfj/speaker-embedding-models` |

- 落到 `assets/models/speech/speaker/`（gitignore），打包进 `Models/speaker/`。
- 校验沿用「固定 SHA-256 + 字节数」，实施时从 hf API 的 `lfs.sha256` 取值后写死。
- 默认按需下载（首次开启开关时触发），`-IncludeSpeaker` 用于需要离线的测试包。
- 发布剔除规则不变；说话人模型与识别模型各自独立可用，缺任一组不影响阶段 1 功能。

## 7. 实施步骤

| # | 步骤 | 验证方式 |
|---|---|---|
| S1 | `LocalSpeechModelCatalog` / `LocalSpeechModelManager` 改为多载荷组，新增 `speaker/` 组 | 现有 129 项测试全绿；`GetStatus` 对两组分别报告 |
| S2 | `Import-BundledSpeechModel.ps1 -IncludeSpeaker` 下载两模型并校验 | 重复运行幂等；错误哈希被拒 |
| S3 | Core 契约：`SpeakerId` / `SpeakerLabel` + `ISpeakerRegistry` | Core 层新增单元测试 |

| S5 | 匹配算法：双阈值、EMA、样本淘汰、低置信度保护 | 表驱动单测（构造向量覆盖命中/新建/误匹配保护） |
| S6 | `SpeakerChangeDetector` + `PyannoteSegmentSplitter` | 用两段公开 wav 拼接的合成样本验证切分点误差 |

## 8. 标定与验收

1. **素材**：脚本化双人对话——两位不同性别 + 两位同性别相近声线各一组，中英各一组；16 kHz；至少覆盖「不同距离/音量」两档，以逼近 VRChat 空间音频的声纹漂移。
2. **阈值扫描**：统计同一人跨句与不同人跨句的相似度分布，取误认率 ≤2% 对应的 `CrossSessionThreshold`、误聚率 ≤5% 对应的 `SessionThreshold`。
3. **端到端**：跑 S7 后的完整链路，统计 §1 表内各项。
4. **跨会话**：同一段音频跑两次（第二次启用声纹库），确认命名被沿用且无误认。
5. **回归**：关闭开关重跑阶段 1 验收脚本，结果应与阶段 1 一致。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| VRChat 空间音频使同一人跨会话/跨位置声纹漂移 | 跨会话阈值从严；认不出退回「说话人X」并可再命名；多样本覆盖不同距离 |
| 同性别相近声线混淆 | 提供合并/重命名纠正；标定素材专门包含相近声线一组 |
| 两人同时说话（重叠语音）污染嵌入 | 低置信度不更新声纹；重叠时沿用上一标签 |
| 误匹配把别人的话挂到已命名者名下 | 双阈值 + 误认率 ≤2% 硬指标 + 「这不是小明」一键纠正并降权样本 |
| 每句多付嵌入成本 | 只对 ≥1.5 s 的段做嵌入；切分只对疑似句；开关可整体关闭 |
| 声纹是生物特征 | 仅本机、未命名不落盘、可清空、文档声明、不上传 |
| 更换嵌入模型导致声纹库不可比 | 声纹库记录 `embeddingModel` + `dim`，不一致时提示重建并备份 |
| ja/ko 说话人区分度未知（候选嵌入模型以 zh/en 训练） | 列为首批标定项；不足时改用 `nemo_en_titanet_large`（101 MB）或降级为「仅 zh/en 命名」并说明 |

## 10. 待定项（需实测决定）

- 嵌入模型最终选型：CAM++ zh+en（28.3 MB）vs. eres2net 系列 vs. titanet。
- `SplitThreshold`、pyannote `WindowShiftRatio`、单段最大切分数（当前 3）。
- 说话人模型是否并入主包（+30 MB）还是恒为按需下载。
- 「自动记住未命名说话人」是否需要，以及默认值。
