# 待办缺陷与改进记录

用户确认后才执行。每条记录现象、影响、方向与状态；标注「待排期」的条目**不实现**。

## D1 · 他人语音长对话消息堆叠，无法查阅

- **状态：待排期（用户明确要求：本阶段任务完成后再议，先不执行）**
- **现象**：语速很快的长对话里，字幕把连续多句一次性堆在一起输出，成了一整块文字，无法逐条查阅。
- **期望**：改成消息条滚动列表（类似 QQ / 微信）——每条一句、可上下滚动回看历史、新消息自动滚到底。
- **影响面**：只涉及字幕的呈现与消息模型（`SubtitleOverlayWindow` / `OverlayWindowHost` / `SubtitleSpeechSession` 的输出路径），**不涉及识别与翻译链路**。

### 已确认的产品决定

| 问题 | 决定 |
| --- | --- |
| 是否持久化历史 | **不持久化**：消息只存在于当前运行期间，不写磁盘 |
| 是否提供「清空」 | **不提供**清空按钮 |
| 暂停时的行为 | **保持现状**：暂停即停止追加，不清空、不改变已有消息 |
| 与现有「原文 + 译文」结构 | **合并为同一条消息**，不新增一层结构 |
| 呈现内容 | **可选**：仅译文 / 译文 + 原文 |
| 说话人标签 | 开启说话人区分时随消息呈现（沿用现有标签） |

### 待定（实施前需要确认）

- 消息条数上限与内存占用（不持久化也不能无限增长）；
- 暂停后重新开始：是否接着已有消息继续追加（默认应继续）；
- 多显示器与窗口缩放下的滚动条与自动滚底策略；用户上翻时不得强制拉回底部。

- **测试素材**：B 站视频 <https://www.bilibili.com/video/BV1dEY76fEn2/> —— 用户指定的音频测试素材，本现象即由此发现。

## D2 · 术语库卡片前端细节

- **状态：待排期（用户明确：仅记录，先不执行）**
- **现象与要求**（用户提供了截图）：
  1. **删除「保存」按钮**：术语表是自动保存的，这个按钮多余且误导；
  2. **删除「启用」文字**：开关本身已有「开 / 关」提示，重复；
  3. **标题与控件对齐**：术语库卡片的标题、开关、表头等对齐需要统一（与其它卡片的对齐规范一致）。
- **影响面**：翻译页术语库卡片（XAML 为主 + 少量 code-behind 事件解绑），**不涉及术语表存储与匹配逻辑**。
- **注意**：删除「保存」按钮后要确认自动保存的触发点覆盖原有的手动保存语义（增删改术语后立即落盘），避免改出"看起来保存了其实没落盘"。
## D3 · 「字幕」快捷键的名称与实际职责不符；并取消暂停识别

- **状态：待排期（本次仅记录，未实施）**
- **现状**：F7 目前**只**切换字幕浮窗的显示/隐藏，不影响他人语音识别（识别由语音页的开始/停止按钮控制）。
- **要求（用户已澄清）**：
  1. **让 F7 同时开关语音识别**：按下时“开”＝开始他人语音识别 + 显示字幕浮窗；再按下“关”＝停止识别 + 隐藏浮窗。
     即这条快捷键成为整个“他人语音 → 字幕”功能的总开关。
  2. **改名**：它的职责从“只管子幕”变成“识别 + 字幕”，所以不能再叫「字幕」。
  3. **不新增快捷键**：不要为“暂停识别”单独加一条，一切合并在这一条上。
- **建议名称（待用户确认，倾向第一个）**：
  | 候选 | 说明 |
  | --- | --- |
  | **他人语音** | 与侧边栏页面名「语音」呼应；设置页三行变成「打开输入框 / 他人语音 / 自身语音」，三者平行、最好记 |
  | 他人语音识别 | 更直白，但略长 |
  | 语音字幕 | 强调产出物，弱化“识别”这层职责 |
- **影响面**：设置页快捷键行文案与提示语（现为“打开 / 关闭字幕”）、指南页快捷键表、语音页与浮窗的快捷键提示、
  F7 的行为接线（`HotkeyActionRouter` / `MainWindow` / `VoiceSessionHost` 的启停路径）；**不涉及识别模型与翻译逻辑**。
- **需要注意的行为后果（实施时一并确认）**：
  - F7 变成“全开 / 全关”后，只想暂时藏起浮窗的用户会被连带停止识别；
    语音页上的「打开字幕」按钮仍应只切换浮窗可见性（不停止识别），保留这种“只藏窗口”的用法；
  - 识别启动需要模型就绪：模型未就绪时按 F7 应给一次明确提示（而不是静默无反应）；
  - 浮窗隐藏与识别停止必须走同一条串行化路径，避免“窗口藏了但识别还在跑”或反之的中间态。
